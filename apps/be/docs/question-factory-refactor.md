# Question Factory 리팩토링 배경 문서

> **브랜치**: `question-factory` (신규, `main` 기반)
> **이전 구현**: `feat/#30` 브랜치

---

## 1. 기존 구현 요약

### 1.1 생성 방식

Naver Clova Studio(HCX-007) LLM에 프롬프트를 보내 질문(Blueprint)을 JSON 배열로 생성하는 파이프라인이다.

**두 가지 모드**가 존재한다:

| 모드  | 설명                                                          | 생성 단위           |
| ----- | ------------------------------------------------------------- | ------------------- |
| Topic | 특정 토픽에 대해 `concept_level × question_depth` 조합별 생성 | 3레벨 × 3깊이 = 9셀 |
| Term  | 단일 용어에 대해 정의 중심 질문 생성                          | depth=Low 고정, 1셀 |

### 1.2 질문 스키마 (Blueprint)

```typescript
{
  domain: "OS" | "Network" | "DB" | "Data_Structure";
  topic_id: string;
  concept_level: "Basic" | "Intermediate" | "Advanced";
  question_depth: "Low" | "Mid" | "High";
  prompt: string;          // 한국어 질문, 20~120자, "요?"로 끝남
  intent: string;          // "정의 확인" 등
  must_include: string[];  // 3~5개 핵심 키워드
}
```

### 1.3 난이도 기준

**Concept Level** (커리큘럼에서 정의):

| 레벨         | 정의                                   |
| ------------ | -------------------------------------- |
| Basic        | 단일 개념으로 설명 가능한 용어         |
| Intermediate | Basic 2~3개 개념 융합이 필요한 용어    |
| Advanced     | Basic 4개 이상 개념 융합이 필요한 용어 |

**Question Depth** (프롬프트 내 규칙):

| 깊이 | 초점                   | 키워드 규칙                               |
| ---- | ---------------------- | ----------------------------------------- |
| Low  | 정의/what 중심         | "왜, 설계, 트레이드오프" 사용 금지        |
| Mid  | 중간 복잡도            | 별도 제약 없음                            |
| High | 설계/판단/트레이드오프 | "왜, 설계, 트레이드오프" 중 1개 이상 필수 |

### 1.4 중복 제거 (Deduplicator)

**1단계: Fingerprint (완전 일치 검사)**

`domain + topic_id + concept_level + question_depth + sorted(must_include)`를 정규화해 문자열로 만든 뒤 Set에 저장한다.
이미 존재하는 fingerprint와 동일하면 중복으로 판정한다.

- 목적: LLM이 여러 호출에서 **완전히 동일한** 질문을 반복 생성하는 것을 방지
- 한계: must_include 순서만 다른 경우는 잡지만, 표현이 조금이라도 다르면 통과됨

**2단계: Jaccard 유사도 (유사 질문 검사)**

같은 `(domain, topic_id, concept_level, question_depth)` 그룹 내에서 prompt 텍스트의 단어 집합을 비교한다.
두 prompt의 Jaccard 유사도가 0.8 이상이면 중복으로 판정한다.

```
Jaccard(A, B) = |A ∩ B| / |A ∪ B|
```

- 목적: "프로세스와 스레드의 차이점은?" vs "프로세스와 스레드의 주요 차이점은?" 같은 **표면적으로 유사한** 질문 필터링
- 한계: 표현이 다르지만 의미가 같은 질문은 잡지 못함 ("스레드가 프로세스와 어떻게 다른가요?" 등)

**3단계: 기존 데이터 시딩**

이전 실행에서 생성된 JSONL 파일을 로드해 Deduplicator에 미리 등록하여, 실행 간 중복도 방지한다.

### 1.5 검증 규칙 (Validator)

| 검증 항목         | 규칙                                           |
| ----------------- | ---------------------------------------------- |
| prompt 길이       | 20~120자                                       |
| prompt 어미       | "요?" 또는 "요？"로 끝남                       |
| must_include 개수 | 3~5개                                          |
| must_include 중복 | 대소문자 무시 기준 중복 없어야 함              |
| Low depth 키워드  | "왜, 근거, 설계, 선택, 트레이드오프" 포함 불가 |
| High depth 키워드 | 위 키워드 중 1개 이상 포함 필수                |

### 1.6 LLM 프롬프트 구조

프롬프트는 다음 정보를 LLM에 전달한다:

- domain, topic/term 이름
- 지정된 concept_level, question_depth
- 출력할 아이템 개수
- Blueprint JSON 스키마
- Low/High depth 규칙
- (Term 모드) 첫 번째 아이템을 정의형 질문으로 고정하는 "Pinned item" 지시

별도의 **few-shot 예시나 난이도별 구체적 가이드**는 포함하지 않는다.

## 2. 기존 방식의 문제점

### 2.1 의미적 중복을 잡지 못함

현재 중복 제거는 **텍스트 표면** 기반이다:

```
✅ 잡아냄: "프로세스와 스레드의 차이점은 무엇인가요?"
            "프로세스와 스레드의 주요 차이점은 무엇인가요?"  (Jaccard ≥ 0.8)

❌ 놓침:   "프로세스와 스레드의 차이점은 무엇인가요?"
            "스레드가 프로세스와 어떻게 다른가요?"            (다른 단어 → Jaccard < 0.8)
```

같은 개념을 다른 표현으로 묻는 질문이 다수 생성되어 질문 뱅크의 다양성이 떨어진다.

### 2.2 난이도 기준이 모호함

**Concept Level 문제:**

- "Basic 2~3개 융합"이라는 기준은 LLM에게 충분히 구체적이지 않다
- LLM은 이 기준을 일관되게 적용하지 못해 Basic과 Intermediate, Intermediate와 Advanced의 경계가 불분명하다
- 프롬프트에 난이도별 구체적 예시가 없어 LLM이 자의적으로 판단한다

**Question Depth 문제:**

- Low는 키워드 금지, High는 키워드 필수로 제어하지만, **Mid에는 아무 제약이 없다**
- 결과적으로 Mid 질문이 Low와 구분되지 않거나, High와 겹치는 경우가 빈번하다
- 키워드 유무만으로는 질문의 실제 인지적 깊이를 보장할 수 없다

### 2.3 프롬프트가 추상적임

- LLM에게 "concept_level: Basic"이라는 레이블만 전달하고, 어떤 수준의 질문을 기대하는지 구체적 예시(few-shot)가 없다
- "정의/what 중심"이라는 지시가 있지만, Basic-Low와 Intermediate-Low의 차이를 구분하는 가이드가 없다
- 결과물의 품질이 LLM의 해석에 의존하여 일관성이 낮다

---

## 3. 새 브랜치에서 작업하는 이유

1. **구조적 변경 범위가 큼**: 난이도 기준 재정의, 프롬프트 재설계, 중복 제거 로직 교체 등 question-factory의 핵심 모듈 대부분을 수정해야 한다
2. **실험적 접근 필요**: 여러 개선 방안을 시도하고 비교해야 하므로, 기존 작업과 분리된 환경이 필요하다
3. **안전한 롤백**: 기존 `feat/#30`의 작업물을 보존하면서, 새 접근이 실패해도 쉽게 되돌릴 수 있다
4. **리뷰 용이성**: 기존 기능 구현 커밋과 품질 개선 커밋이 섞이지 않아 PR 리뷰가 명확해진다

## 4. 개선 방향 (검토 중)

| 방안                    | 설명                                                                            |
| ----------------------- | ------------------------------------------------------------------------------- |
| **프롬프트 강화**       | 난이도별 few-shot 예시, Bloom's Taxonomy 매핑, 금지/필수 패턴을 프롬프트에 명시 |
| **시맨틱 중복 제거**    | Jaccard 대신 임베딩 기반 코사인 유사도로 의미적 중복 탐지                       |
| **Mid depth 기준 신설** | Mid에도 명확한 키워드/패턴 규칙을 부여하여 Low/High와 구분                      |
| **LLM 후처리 검증**     | 생성 후 별도 LLM 호출로 난이도 재평가 (cross-validation)                        |
| **레퍼런스 답변 포함**  | Blueprint에 기대 답변 수준을 포함하여 난이도를 간접 제어                        |
